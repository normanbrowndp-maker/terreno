## Правила исполнения

Каждая задача заканчивается независимо проверяемым результатом. До правки: состояние файлов/Git, зависимости, короткий план, checkpoint. Затем минимальный diff, релевантные проверки и регрессия, исправления, документация. После появления Git checkpoint — локальный commit без секретов; до Git — проверенная файловая копия. Чужие незакоммиченные изменения не перезаписывать.

Команды/пути TRAVEL-005…008 уже созданы в фундаменте, перечисленные интерфейсы следующего каталожного этапа остаются планом. Версии закреплены в package/lock/runtime. Cloud/production, платные API, destructive SQL и переход к этапу2 не включены в разрешённые действия. Исторические snapshot checks этапа0 сохраняются; актуальный quality gate — npm run check.

## Первые 10 небольших задач

### TRAVEL-001 — Исходный аудит и безопасная контрольная точка

- **Цель:** установить проверяемое состояние проекта до изменений.
- **План реализации:** перечислить скрытые файлы; проверить инструкции/Git/манифесты/схему/тесты; проверить окружение; снять копию с SHA-256; записать факты и ограничения.
- **Зависимости:** read-доступ к папке и write-доступ к разрешённому temp; приложения/БД не требуются.
- **Файлы результата:** AUDIT_REPORT.md, audit/baseline.json, audit/BASELINE.md.
- **Критерии приёмки:** все исходные170 файлов перечислены и сохранены; источники фактов указаны; отсутствие приложения не названо успешным тестом; локальная служба PostgreSQL учтена.
- **Тесты:** сравнение SHA-256 каждой копии/оригинала, read-only inventory, фиксация ожидаемого Git failure; verify_stage0.py проверяет неизменность originals.
- **Риски:** пропустить скрытые файлы; принять клиентскую версию PostgreSQL за серверную. Обход force и явные оговорки снижают риск.
- **Статус:** **выполнено**, свидетельства в AUDIT_REPORT и audit/VALIDATION.

5. **Failure в чистой среде:** frozen install, DB outage и restore — TRAVEL-005/008.
