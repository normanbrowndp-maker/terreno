# Следующий этап Neon bootstrap — предложение после TRAVEL-023

**Статус:** только план; выполнение, cloud SQL, credentials retrieval, создание ролей/расширений и активация targets **не разрешены** TRAVEL-023. Исходный ресурс уже создан — новый проект или новая БД не нужны. Следующий номер задачи выдаётся при согласовании.

**Цель:** подготовить существующую travel_test_foundation к безопасной работе отдельно от локальных БД; не переносить пример infra/local/init.sql в облако. **Зависимости:** новое разрешение владельца на точный bootstrap scope и безопасный административный доступ; повторная metadata сверка [реального tuple](NEON_TARGET_REGISTRATION.md); audit-ready минимальные SQL/rollback меры без destructive migrations.

1. **Согласовать способ административного доступа и хранения секретов.** Только Нурман/norman, project broad-wind-62771105, branch br-mute-river-bavdwjwl, direct ep-curly-moon-ba3f3csy, DB travel_test_foundation, проверяемый TLS. Bootstrap выполняется отдельным явно разрешённым административным каналом, не runtime resolver; не отключать registry guards ради первого SQL. Credentials получают только в рамках нового разрешения, не выводят и не коммитят; `.env.local` не переписывают. Не получать и не менять секреты gloomi/sidequest.
2. **Снять исходные SQL evidence в пределах новой тестовой БД.** Фактические session/current role, database/owner, server/extension versions, schemas, role flags/memberships и ACL, отсутствие чужих данных. При несовпадении metadata/ожиданий — остановка. Наличие PostGIS и конкретная версия пока неизвестны; версия из документации не равна установленной.
3. **Утвердить и создать минимальные роли отдельным SQL-планом.** Предлагаемые имена travel_test_runtime и travel_test_migrator — сейчас только контракт активной схемы, не существующие роли. Обе без SUPERUSER/CREATEDB/CREATEROLE/REPLICATION/BYPASSRLS/neon_superuser и доступа к bootstrap role; runtime без migrator membership. Не использовать admin-default Console/API role creation для runtime. [Официальные правила Neon roles](https://neon.com/docs/manage/roles). Предусмотреть запрет лишних SET ROLE возможностей и аудит транзитивных memberships.
4. **Согласовать ownership и extensions.** Существующий guard требует migrator как владельца тестовой БД; текущий владелец по metadata — bootstrap owner. Передача ownership внутри новой тестовой БД — явно обозримая часть будущего SQL scope; не распространять на другие БД. Bootstrap устанавливает postgis/pg_trgm после проверки доступности; не выдавать runtime права установки расширений. [PostGIS в Neon](https://neon.com/docs/extensions/postgis). Измерить и записать фактическую версию/совместимость с6 неизменными миграциями.
5. **Отдельный identity marker и ACL.** public.travel_neon_test_identity — обычная bootstrap-owned таблица ровно с одной строкой actual project/branch/endpoint/database/purpose=test; это отдельный bootstrap artifact, не изменение старых6 SQL файлов. Runtime/migrator получают только SELECT marker, без table/column modification. Отозвать PUBLIC CREATE/TEMP и лишние default privileges; runtime получает CONNECT, нужные schema USAGE и SELECT, без DB/schema ownership, column write и sequence USAGE/UPDATE. Проверить дополнительные схемы/SECURITY DEFINER-функции, чтобы read-only не опирался только на table ACL. Ownership marker сохраняется за bootstrap после передачи database ownership.
6. **Проверить положительные и отрицательные сценарии перед активацией.** Реальный TLS с проверкой сертификата, current_user/session_user, identity mismatch, попытки runtime писать/создавать объекты/TEMP/менять marker/SET ROLE; мигратор не меняет marker и не получает admin. При отсутствии нужных прав/версии/marker — отказ, не ослабление guard. Не считать служебные migration flags частью management evidence.
7. **Только после evidence и отдельного review изменить registry.** Перечитать management tuple, подтвердить SQL roles/ACL/marker и секреты в выделенном test-процессе. Удалить pending запись и добавить полную active запись единым проверяемым изменением (не оставлять duplicate endpoint). Перенос вручную не является разрешением запускать migration/seed; активировать штатный клиент только в согласованном smoke scope.
8. **Миграции/seed и Railway — последующие ворота.** Разрешённые позже migrations используют только direct connection, прежние session advisory locks/checksums/order/transaction и исходные6 SQL; runtime — pooled read-only. [Почему direct](https://neon.com/docs/connect/connection-pooling). Seed отдельно, demo отдельно от production. Railway/deploy/paid upgrades не входят в bootstrap.

**Критерии приёмки будущего bootstrap:** воспроизводимый minimal SQL plan, real evidence всех ролей/ACL/marker/extensions/TLS, отрицательные smoke с fail-closed результатом, отсутствие секретов в logs/Git, неизменность чужих проектов/локальных БД/старых миграций. **Риски:** broad inherited admin, частичный bootstrap, невыполнимая ownership передача, marker cloning, несовместимые PostGIS версии, утечка credentials, Free exhaustion. При ошибке не удалять проект/БД/роли и не выполнять destructive rollback автоматически; записать фактическое состояние и остановиться.
