## Доступность и область инструкций

До этой задачи корневого AGENTS.md и родительских AGENTS.md в проверенной цепочке до C:\ не было. Два найденных AGENTS.md находились внутри vercel-react-best-practices и vercel-composition-patterns: это compiled guides. Новый [корневой AGENTS.md](../AGENTS.md) задаёт общие правила проекта.

Пять проектных скиллов физически находятся в `.agents/skills/`, присутствуют в skills-lock.json и в предоставленном каталоге текущей сессии. Это подтверждает возможность прочитать и применить инструкции сейчас. Будущая сессия должна повторно проверить свой каталог; наличие файла само по себе не доказывает автоматическое обнаружение любым другим IDE/клиентом. Отдельный плагин/сервер для этих Markdown-скиллов в проекте не обнаружен и не требовался для чтения.

`skillPath` в lock — путь в исходном репозитории пакета, а не обязательный локальный путь. Поэтому `.claude/skills/...` в metadata ui-ux-pro-max не означает отсутствия локальной `.agents/skills/...` копии. SHA-256 оригиналов проверены по baseline; соответствие computedHash алгоритму установщика/remote commit не заявляется.

## Алгоритм выбора для каждой задачи

1. Определить результат и изменяемую поверхность: документация, сервер, SQL, React, UX, security, browser test.
2. Прочитать относящиеся требования/ADR и применимый SKILL. Выбирать минимальный достаточный набор; не вводить жёсткий лимит, мешающий существенной security/regression проверке.
3. Кратко сообщить выбранные скиллы и причину. Подробные rules/references загружать по необходимости, не все 170 файлов для каждой правки.
4. Для неоднозначного совета проверить версии/официальный первичный источник. Пример библиотеки не становится автоматически архитектурным решением проекта.
5. Выполнить только разрешённую работу, проверить результат обычными инструментами и обновить задачу. Если специального скилла нет — работать по контракту/официальной документации, не устанавливать неизвестный пакет автоматически.
